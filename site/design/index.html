Palette vs roles. The swatches above are the palette — what each colour is. Components use roles — what each colour is for: --bg, --surface, --line (every border and shadow), --inverse (dark panels), --on-accent (text on gold or pink), --text-ink, --text-teal, --text-accent. In light mode every role equals a palette colour; dark mode changes only the roles. --success and --danger are text roles — a danger fill names --terracotta, because a fill and a text colour need different shades in the dark.

Rules that are load-bearing

1. Never write a raw hex outside tokens/. Fixing every contrast failure on the site was a three-line change precisely because nothing hardcodes colour. One #somehex in a component breaks that property permanently.
2. Gold is a fill and border colour. Never small text on a light surface. At 1.69:1 on cream there is no adjustment that saves it — it is used on plum, or as a background with plum text on top.
3. A colour has to pass in both directions. Any value used as text on a light surface and as a fill under light text must clear 4.5:1 both ways. That is why terracotta and teal are the shades they are.
4. class styles, data-* targets. JavaScript queries [data-stack], never .skills. Renaming a class for visual reasons must never break behaviour.
5. Motion is physical, and optional. Hover lifts, active presses, nothing fades. All of it is disabled under prefers-reduced-motion: reduce.
